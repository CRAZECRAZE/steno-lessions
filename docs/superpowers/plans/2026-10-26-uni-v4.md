# Uni v4 Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Practice steno-lessions on the real Uni v4 — a toggleable diagram of the board's 28-key layout, and strokes read straight from the machine over WebHID (Plover HID protocol) — while the QWERTY way of using the site stays untouched.

**Architecture:** A new pure UMD lib (`public/lib/uni.js`) owns the Plover HID wire format, the lever→steno-slot mapping, and the board's physical grid — Node-testable like `steno.js`/`lessons.js`. `app.js` gains: a diagram-mode toggle (QWERTY | Uni v4, one visible at a time), a Uni diagram renderer reusing the existing `.key` classes, and a unified chord pipeline where QWERTY key events and HID state reports both feed `state.chordBits` and only finish a chord when *both* sources are empty. WebHID is progressive enhancement: no device, no WebHID, no problem.

**Tech Stack:** Vanilla JS (UMD lib pattern, no dependencies), WebHID API, `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-26-uni-v4-design.md`

## Global Constraints

- Vanilla JS only; no new dependencies, no build step, no framework.
- New lib files follow the repo's UMD pattern (Node `module.exports` + `window` global), like `public/lib/steno.js`.
- Test command is `npm test` (= `node --test test/*.test.js`); Node ≥ 18.
- The app's house style: comments explain *why*, `$ = (id) => document.getElementById(id)`, DOM built with `createElement`/`textContent` (no innerHTML for user data).
- Existing behavior must not change when no Uni is connected and mode is QWERTY: same renders, same key handling, same tests passing.
- Plover HID wire format (from `plover/machine/plover_hid.py`, verbatim): usage page `0xFF50`, usage `0x4C56`, report id `0x50`, 8-byte big-endian 64-bit lever state; chart order `S1- T- K- P- W- H- R- A- O- *1 -E -U -F -R -P -B -L -G -T -S -D -Z #1 S2- *2 *3 *4 #2 #3 … #C X1 … X26` (bit 63 = `S1-`, bit i from MSB = chart[i]).
- The Uni's 28 levers are exactly chart indices 0–27; `S1-`/`S2-` → slot `S-`, `*1`–`*4` → slot `*`, `#1`/`#2` → slot `#`, `X*` → ignored.

## Review Focus

The five inputs most likely to bite a person, each pinned to its owning task:

1. **A stray all-zero report with no chord in progress** (connect while keys half-pressed, or a repeated zero report) must not fabricate a mistake or blank the preview — `finishChord` may only run when `state.chordBits !== 0`. Pinned in Task 3's smoke list and guarded in Task 3's code step.
2. **Board unplugged mid-lesson** — the page must fall back to QWERTY silently-with-a-message; no stuck amber keys, no thrown errors from later reports. Pinned in Task 3's smoke list; handler code step.
3. **Browser without WebHID (Firefox/Safari)** — the connect button is present but disabled with a one-line reason; diagram toggle and everything else keeps working. Pinned in Task 3's code step (feature detection) and Task 4's smoke list.
4. **Reports carrying X1–X26 / unused #3–#C bits** (other boards on this protocol) — ignored for chords, never crash the chart walk. Pinned by Task 1's `strokeBits(['X1']) === 0` and `strokeBits(['#3'])` slot-merge tests.
5. **Uni mode on a static host / before data load** — the diagram renders from `UNI_KEYS` + loaded bundle sounds; if the bundle hasn't loaded, the toggle still switches containers without throwing. Pinned in Task 2's regression step and smoke list.

### Task 1: `public/lib/uni.js` — Plover HID parsing, lever map, board grid

**Files:**
- Create: `public/lib/uni.js`
- Test: `test/uni.test.js`

**Interfaces:**
- Consumes: `StenoData` (`S.SLOTS` — array of `[letter, slotName]` in bit order, `S.displayOrder`, `S.namesInBits`, `S.displayName`) via the UMD factory argument, exactly as `lessons.js` consumes `WordFreq`.
- Produces (all exported from `window.UniV4` / `module.exports`):
  - `USAGE_PAGE = 0xFF50`, `USAGE = 0x4C56`, `REPORT_ID = 0x50`
  - `CHART: string[64]` — the Plover HID chart, verbatim
  - `parseHidState(reportId: number, payload: array-like) -> bigint | null` — null unless `reportId === 0x50` and `payload.length >= 8`; else big-endian 64-bit int of `payload[0..8)`. (Amended after Task 1's interim review: WebHID strips the report id into `event.reportId`, unlike Plover's hidapi reads which keep it as the first data byte — so the caller passes the id and payload separately.)
  - `chartKeys(state: bigint) -> string[]` — chart names for set bits, chart order
  - `leverSlot(name: string) -> string | null` — lever name → lesson slot (`S-`/`*`/`#`/identity) or null for `X*`
  - `strokeBits(names: string[]) -> number` — OR of `1 << slotIndex(leverSlot(name))`, unknown → contributes 0
  - `UNI_KEYS: { name: string, slot: string, half: 'L'|'R', row: 0|1|2, col: number }[28]` — the board grid (below)
  - `hintNames(bits: number) -> string[]` — `S.displayOrder(S.namesInBits(bits)).map(S.displayName)`

  `UNI_KEYS` grid (from the QMK `the_uni` LAYOUT and the official layout SVG, verified):
  - row 0, left (col 0–3): `S1- T- P- H-`; row 0, right (col 0–5): `*3 -F -P -L -T -D`
  - row 1, left (col 0–3): `S2- K- W- R-`; row 1, right (col 0–5): `*4 -R -B -G -S -Z`
  - row 2 (thumb), left (col 2–4): `#1 A- O-`; right (col 0–2): `-E -U #2`

const test = require('node:test');
const assert = require('node:assert');
const U = require('../public/lib/uni.js');

test('parseHidState accepts report id 0x50 with an 8-byte big-endian payload', () => {
  assert.strictEqual(U.parseHidState(0x50, [0x80, 0, 0, 0, 0, 0, 0, 0]), 1n << 63n);
  assert.strictEqual(U.parseHidState(0x50, [0, 0, 0, 0, 0, 0, 0, 0x01]), 1n);

test('parseHidState rejects wrong report id and short payloads', () => {
  assert.strictEqual(U.parseHidState(0x51, [0x80, 0, 0, 0, 0, 0, 0, 0]), null);
  assert.strictEqual(U.parseHidState(0, [0x80, 0, 0, 0, 0, 0, 0, 0]), null);
  assert.strictEqual(U.parseHidState(0x50, [0x80, 0]), null);
  assert.strictEqual(U.parseHidState(0x50, null), null);

test('chartKeys reads chart names from the MSB down', () => {
  assert.deepStrictEqual(U.chartKeys(1n << 63n), ['S1-']);
  assert.deepStrictEqual(U.chartKeys((1n << 63n) | (1n << 62n)), ['S1-', 'T-']);
  assert.deepStrictEqual(U.chartKeys(1n << 40n), ['S2-']);
  assert.deepStrictEqual(U.chartKeys(0n), []);
});

test('leverSlot maps split levers onto lesson slots and ignores X keys', () => {
  assert.strictEqual(U.leverSlot('S1-'), 'S-');
  assert.strictEqual(U.leverSlot('S2-'), 'S-');
  assert.strictEqual(U.leverSlot('*3'), '*');
  assert.strictEqual(U.leverSlot('#1'), '#');
  assert.strictEqual(U.leverSlot('#C'), '#');
  assert.strictEqual(U.leverSlot('X1'), null);
  assert.strictEqual(U.leverSlot('T-'), 'T-');
  assert.strictEqual(U.leverSlot('-Z'), '-Z');

test('strokeBits merges levers onto slot bits', () => {
  const sBit = 1 << S.SLOTS.findIndex(([, name]) => name === 'S-');
  const starBit = 1 << S.SLOTS.findIndex(([, name]) => name === '*');
  const hashBit = 1 << S.SLOTS.findIndex(([, name]) => name === '#');
  assert.strictEqual(U.strokeBits(['S1-', 'S2-']), sBit);
  assert.strictEqual(U.strokeBits(['*1', '*2', '*3', '*4']), starBit);
  assert.strictEqual(U.strokeBits(['#1', '#2']), hashBit);
  assert.strictEqual(U.strokeBits(['X1']), 0);

  assert.strictEqual(positions.size, 28);

  const aBit = 1 << S.SLOTS.findIndex(([, name]) => name === 'A-');

```js
// The Uni v4 (Plover HID firmware) speaks its state over WebHID: every state change is one
// report - report id 0x50, then 8 bytes of a 64-bit lever bitmask. A stroke is the state
// going non-empty and then back to all-zero, which mirrors finishChord's last-key-up model.
// Reports are snapshots, so each non-zero report is OR-ed into the chord: a lever that went
// down and up mid-stroke is kept, exactly like Plover's own accumulation.
let uniDevice = null;
function setUniStatus(text) { $('uni-status').textContent = text; }

async function connectUni() {
  if (!navigator.hid) {
    setFeedback('The Uni v4 needs a Chromium browser (Chrome, Edge, Chromium) for WebHID.', 'bad');
    return;
  }
  try {
    const [device] = await navigator.hid.requestDevice({ filters: [{ usagePage: U.USAGE_PAGE, usage: U.USAGE }] });
    if (!device) { setFeedback('No Uni selected.', 'bad'); return; }
    await device.open();
    uniDevice = device;
    device.addEventListener('inputreport', onUniReport);
    device.addEventListener('disconnect', onUniDisconnect);
    setUniStatus('connected');
    setFeedback('Uni v4 connected. Its keys type here; QWERTY still works too.', 'good');
  } catch (error) {
    setFeedback(`Could not connect the Uni v4: ${error.message}`, 'bad');
  }
}

function onUniReport(event) {
  // WebHID strips the report id into event.reportId (Plover's hidapi reads keep it as the
  // first data byte) - pass both halves to the parser separately.
  const payload = new Uint8Array(event.data.buffer, event.data.byteOffset, event.data.byteLength);
  const state64 = U.parseHidState(event.reportId, payload);
  if (state64 === null) return;
  if (state.paused) { if (state64 !== 0n) resume(); else return; }
  const levers = U.chartKeys(state64);
  if (state64 === 0n) {
    state.uniPressed.clear();
    if (state.pressed.size === 0 && state.chordBits !== 0) finishChord();
  } else {
    if (state.pressed.size === 0 && state.uniPressed.size === 0) {
      state.chordBits = 0;
      state.chordStart = performance.now();
    }
    for (const name of levers) state.uniPressed.add(name);
    state.chordBits |= U.strokeBits(levers);
  }
  renderChord();
}

function onUniDisconnect() {
  uniDevice = null;
  state.uniPressed.clear();
  setUniStatus('');
  setFeedback('Uni v4 disconnected. QWERTY typing still works.', 'bad');
  renderChord();
}

function setupUni() {
  const button = $('connect-uni');
  if (!navigator.hid) {
    button.disabled = true;
    setUniStatus('Needs a Chromium browser');
    return;
  }
  button.addEventListener('click', connectUni);
}
```
